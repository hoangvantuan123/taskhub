# Directory AUDQ contract

Scope: Skillhub server (`cmd/skillhub`), its HTTP gateway, generated gRPC Directory service, and FE adapters. Legacy ERP databases and services remain separate.

## Naming and identity

Tables use `_<feature code><entity>`. Directory tables: `_USRAccountDirectory`, `_SECGroupDirectory`, `_ORGDirectory` (department/position/job_role), `_LRNCourseDirectory`, `_EXMExamDirectory`, `_SYSSettingDirectory`. Security relationship tables use `_SECGroupMember`, `_SECGroupPermission`, `_SECAccountPermission`, and `_SECPermissionDirectory` stores module/action definitions. Session, audit, node and level-policy tables use USR/SEC/EXM prefixes.

`IdSeq` is a native UUID primary key. New values are UUIDv7, generated by the server/database. FE does not generate or display them. Existing business keys and old external IDs remain unique: migration preserves referenced values and rebuilds their foreign keys against unique constraints, rather than changing historical identities. New APIs accept `id_seq` for U/D and return `IdSeq` in query rows. UUID reference columns (`GroupSeq`, `UserSeq`, `PermissionSeq`, `ParentSeq`, `ActorSeq`, `CreatedBySeq`) are backfilled, indexed and constrained to the referenced IdSeq. Compatibility triggers synchronize UUID and legacy reference values; both old-key writes and UUID-only relationship writes remain supported.

Startup first renames old Skillhub tables in place, then initializes base schemas, then executes `directory_schema.sql`. Conflicting old/new table pairs abort migration rather than merge silently. DDL uses a transaction/advisory lock and a 5-second lock timeout. A database backup is required before rollout. This is a coordinated backend upgrade; do not run old and new binaries concurrently. Reverting only the executable after migration is not supported; restore the matching backup or write a reviewed reverse migration.

## Endpoints

HTTP POST `/api/auth/directory_a`, `_u`, `_d`, `_q` proxy to generated `directory.Directory/A`, `/U`, `/D`, `/Q` methods. Existing session/cookie/Origin policies apply. Request tokens are supplied by the gateway and never trusted from the payload. Every operation checks an active session and resource-specific permissions on the server.

Resources: `accounts`, `groups`, `organization`, `courses`, `exams`, `settings`.

```json
{
  "payload": {
    "resource": "groups",
    "query": {
      "page": 1,
      "page_size": 25,
      "search": ["Biên soạn", "Chấm thi"],
      "search_columns": ["label"],
      "filters": [
        {"column": "enabled", "op": "eq", "values": [true]},
        {"column": "key", "op": "in", "values": ["group_a", "group_b"]}
      ],
      "sort": [{"column": "label", "direction": "asc"}]
    }
  }
}
```

Q returns `{rows, total, page, page_size}`. Search terms are case-insensitive and Vietnamese-accent-insensitive (for example, `bien soan` matches `Biên soạn`) and are OR-ed across the specified searchable columns. Filters are AND-ed; `in` provides multiple alternatives within one column. Supported operators: eq, neq, in, not_in, contains, prefix, gt, gte, lt, lte, is_null, not_null. `%`, `_` and backslashes in search text are escaped as literals. Column names, operators and sort directions are allowlisted, all values use PostgreSQL parameters. Limits: 200 rows/page, 20 filters, 100 values/filter, 20 search values, 256 bytes/search value, 5 sort fields and a 5-second query deadline. `IdSeq` provides a deterministic sorting tie-breaker. Counts and rows use one repeatable-read snapshot.

Common columns: `IdSeq`, `label`, `enabled`; `key` except accounts; organization also `kind`. Accounts Q supports `username`, `email`, `contact_email`, `phone`, `department`, `position`, `job_role`, `role`, `approved`, `registration_source`, and effective `groups` for search/filter/sort where their declared type allows it. Account rows include only the current page plus the fields needed by the account administration screen; password hashes and unpaged account collections are never returned by Q. Every row includes the four audit fields `CreatedBy`, `UpdatedBy`, `CreatedAt`, `UpdatedAt`, plus `CreatedByName` and `UpdatedByName`; actor UUIDs remain available for audit while display names resolve to account names or `Hệ thống`. Only registered columns are accepted; arbitrary SQL, joins, JSON paths and physical table names are rejected.

A sends `{resource,record}`. U sends `{resource,id_seq,row_version,record}`. D sends `{resource,id_seq,row_version}`. `row_version` is the string representation of the `RowVersion` read from Q. A starts at version 1; U and soft D return the committed `RowVersion`; hard D returns `DeletedVersion`. Account D disables the account and revokes sessions; organization D disables the entry, preserving existing references. Other directory D operations delete the selected record. Group mutations reuse the existing permission validation and transactional audit; account mutations reuse password hashing and account protection. A group record is `{label,enabled,permissions:[{module,actions:[]}]}`; a group U must explicitly supply permissions. Generic course/exam/setting records support `{label,enabled,data:{}}` plus an optional immutable creation key. These catalogs do not replace course-content, exam-taking or other domain workflows.

## Frontend and extension

Use `directories.accounts.query({page,pageSize,search,searchColumns,filters,sort})` and the corresponding `directories.*.query(...)` from `src/services/directory/directory.service.js`; `.add(record)`, `.update(idSeq,record,rowVersion)`, `.remove(idSeq,rowVersion)` share the same envelope. `.all()` is for small lookup selectors; listing screens must use Q paging and must not fetch full account collections for client-side filtering. Account administration reads one Q page at a time and requests small organization/group lookup collections separately. Group listing now searches and pages on the server (200ms debounce); semicolon/comma separate quick-search values. Existing membership actions still use retained business keys.

The legacy `people` action is lookup-only (`{lookups_only:true}`) for the organization directory. It rejects account-list requests so a caller cannot retrieve an unpaged dump; account rows are available only through the paged `directory_q` contract.

Register a new resource in `directoryResource`: physical table, required permission scope, and a closed map of logical column names to SQL/type/searchability. Add a mutation hook for sensitive domains rather than allowing arbitrary columns. Add it to the FE registry and document its fields. Typed proto generation from repository root:

```
protoc --proto_path=service/proto --go_out=service/server-core --go_opt=module=server-core --go-grpc_out=service/server-core --go-grpc_opt=module=server-core service/proto/directory.proto
```

B-tree indexes support identity/key lookups. For large datasets with contains search, add reviewed pg_trgm GIN indexes in the deployment environment after checking extension permissions; this migration does not install global extensions automatically. Query latency has not been benchmarked on production-size data.

## Row audit and concurrent writes

All 17 current Skillhub tables have IdSeq (UUIDv7), CreatedBy/UpdatedBy (UUIDv7 foreign keys), CreatedAt/UpdatedAt (timestamptz), and positive bigint RowVersion. API responses serialize RowVersion as a string to preserve bigint precision. Database triggers assign creation metadata and increment the version on each update; clients cannot override the creator or timestamps. The server resolves the authenticated account's canonical IdSeq into a transaction-local actor. Automated operations use the SYSTEM actor in _SYSActorDirectory.

U/D lock and compare the supplied revision inside the mutation transaction. Missing revisions fail validation; stale revisions return gRPC Aborted / HTTP 409 with a reload message. Legacy account, group, module, membership, grant, profile, and password writes also enforce revisions. Bulk account writes accept RowVersions keyed by legacy account ID; membership writes accept versions keyed by group key and increment the group parent revision. Permission child rows are protected through the parent aggregate. Level policies retain their existing expected_version guard for immutable policy snapshots.

Physical deletes record the actor, time, original version, and redacted snapshot in _SYSRowChangeLog. Historical rows with unknown authors use the SYSTEM actor and AuditOrigin=LegacyImport; missing historical timestamps use the migration time. This does not invent historical authors. Existing legacy business columns are retained for compatibility; this rollout does not migrate separate ERP databases or remaining FE mock catalogs.

Local audit rollout: fresh pg_dump backup created before migration; 17/17 tables verified with all six identity/audit fields, 14 accounts and 5 groups preserved, no invalid actor UUID versions or unvalidated foreign keys. Isolated PostgreSQL/gRPC tests cover stale updates/deletes, concurrent writers, immutable creators, and delete history. The scoped Go suite, 16 FE tests, and production FE build pass.
